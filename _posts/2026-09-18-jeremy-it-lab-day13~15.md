## day 13 : 서브넷팅 - 1

1. 클래스 풀(Classful) 주소 체계의 한계와 주소 낭비 문제
    - IANA(Internet Assigned Numbers Authority) : 전세계 IP 주소를 기업/기관의 규모에 맞춰 할당하는 비영리 단체
    - 클래스풀 규칙의 비효울성
        - 초기에는 무조건 Class A(`/8`), Clss B,(`/16`) Class C(`/24`)단위로만 고정 할당했다.
        - case1 : 2의 라우터 IP만 필요한 회선에서 가장 작은 Class C를 주더라도  256개 중 4개(네트워크, 브로드캐스트, R1, R2)만 쓰고 252개의 IP가 낭비된다.
        - case2(5,000 대 호스트를 가진 기업) : Class C로 부족하여 Class B를 받으면 60000개의 주소가 낭비된다.
        - 이로 인해 약 43억 개의 전체 IPv4 고갈 위기를 겪었다.

2. CIDR(Classless Inter-Domian Routing, 사이더)
    - 도입 : 1993년 IPv4 주소 고갈을 막기 위해 기존 고정된 클래스 풀 경계를 완전히 폐기하고 도입한 주소 지정 방식
    
    - `/8` `/16` `/24`의 고정 경계를 없애고, 비트 단위로 네트워크 마스크를 자유롭게 쪼개거나 늘릴 수 있도록 허용했다.
    - 큰 네트워크를 더 작은 단위인 서브넷(Subsnet, 보조 네트워크)으로 쪼개어 필요한 만큼만 효율적으로 주소를 배치할 수 있게 되었다.
    - `/25` `/26`처럼 슬래시 뒤에 마스크 비트 수를 직접 표기하는 방식 자체를 CIDR 표기법(CIDR Notation)이라고 부른다.

3. 서브넷 마스크 확장에 따른 호스트 수 변환 공식(Class C 기준)
    - 네트워크 비트를 오른쪽으로 1비트 빌려올 때마다, 호스트 비트수는 1개씩 줄어들며 호스트 공간은 절반으로 줄어든다. 

4. 특수 목적의 초소형 프리픽스 : `/31` `/32`
    1. `/31` 서브넷(`255.255.255.254`)
        - 호스트 비트가 단 1개이다.
        - 기존 공식인 ($2^1 - 2 = 0$)에 따르면 쓸수 있는 IP가 0개여야 하지만, 라우터와 라우터가 1:1로 직접 맞닿은 Point-Point 링크에서는 네트워크 주소나 브로드 캐스트 주소가 구조적으로 필요가 없다.
         - 따라서 규칙의 예외를 적용하여 오직 2개뿐인 IP(`.0` `.1`)를 양쪽 라우터에 직접 부여한다.
         - `/30` 보다 2개의 IP를 추가로 절약하므로 가장 극대화된 효율성을 제공하는 최신 표준 링크 방식(Cisco 장비 설정시 Point-to-Point확인 경고 메시지 출력)
    
    2. `/32`서브넷(`255.255.255.255`)
        - 호스트 비트 0개이다.
        - 실제 물리 인터페이스에는 할당할 수 없지만, 라우팅 테이블에서 특정 단일 호스트(IP 1개)만을 정확히 지목하는 호스트 라우터 나 Local Route에 사용한다. 

5. 실전 서브넷 크기 결정 시나리오 
    - 요구 조건 : 라우터 R1에 4개의 서브넷이 연결되어 있고, 각 서브넷마다 45대 이상의 호스트(R1인터페이스 포함)를 수용해야 한다. 
    - 최소 필요 크기 판별
        - 네트워크 주소와 브로드 캐스트 주소를 합치면 서브넷 당 최소 47개 이상의 전체 IP가 필요하다. 
        - `/27`(H=5) : $2^5 - 2 = 30$ -> 부족
        - `/26`(H=6) : $2^6 - 2 = 62$ -> 45대 수용 가능
        - 4개의 서브넷 모두에 적용해야 할 공통 최적 서브넷 마스크는 `/26`(`255.255.255.192`)이다.

### 퀴즈

1. `172.30.0.0/16` 네트워크가 부여되었다. 회사는 서브넷 당 최소 500개의 호스트를 수용할 수 있는 서브넷 100개가 필요하다. 어떤 프리픽스 길이를 사용해야 하는가?
    - 해설 : 서브넷 100개가 필요하만 해당 주소를 오른쪽 비트로 밀어 늘려주어야 한다. 
    $2^7 = 128$개 로 100개 이상이 충족된다 -> 기존 `/16` 경계선에서 오른쪽으로 7칸 더 밀어 붙인다.
    호스트 수 검증 : 500개의 호스트가 필요하다. 16-7 = 9이다. $2^9 - 2 = \mathbf{510\text{개}}$ 로 호스트가 최소 500개 필요하다는 조건 또한 만족한다.
    프리 픽스 길이 : 16 + 7 = 23  -> `/23`

2. 호스트 `172.21.111.201/20`은 어떤 서브넷에 속하는가?
    - 해설 : 프리픽스 먼저 계산하면 32-20=12 이므로 `255.255.240.0`이 서브넷 마스크이다. 3번째 옥텟의 마스크를 보면 `1111 0000`으로 $2^4 = \mathbf{16}$ 이다. 즉 3번째 옥텟의 호스트 비트 4개가 자유롭게 바뀔 수 있는 범위가 16개이므로, 하나의 서브넷 덩어리 크기가 16이 되는 것이다. 
    16의 배수로 계산시 111의 의치는 96과 112번 사이에 위치 한다.
    -> 네트워크 주소는 해당 범위의 가장 첫 번째 주소 이므로 3번째 옥텟은 `172.21.96.0`이 된다.

3. `192.168.91.78/26`이 속한 네트워크의 브로드캐스트 주소는 무엇인가?
    - 해설 : 프리픽스의 길이 32-26=6 이므로 4번째 옥텟에 위치한다. `1100 0000`이 서브넷 마스크로 `255.255.255.192`가 된다. 한 블럭의 크기가 64로 설정됨으로 78이 속한 범위는 63~127로 서브넷의 가장 마지막 주소가 브로드 캐스트 주소가 된다.
    -> `192.168.91.127`

4. `172.16.0.0/16` 네트워크를 동일한 크기의 4개 서브넷으로 분할한다. 두번째 서브넷의 네트워크 주소와 브로드캐스트 주소를 구하시오
    - 해설 : 4개의 서브넷으로 분할 해야 하므로 프리픽스를 오른쪽으로 2칸 옮겨 프리픽스가 18이 되게 한다. 그럼 서브넷 마스크가 `255.255.192.0`이 된다. 블럭의 크기가 64이기에 그중 2번째 서브넷인 블럭을 고려하면 네트워크 주소와 브로드 캐스트 주소를 구할 수 있다.
    브로트 캐스트 주소의 호스트 부분의 비트를 모두 1로 설정한다.
    -> 네트워크 주소 : `172.16.64.0`, 브로드캐스트 주소 : `172.16.127.255`

5. `172.30.0.0/16`네트워크를 각각 1,000개의 호스트를 수용할 수 있는 서브넷으로 분할한다. 몇 개의 서브넷을 만들 수 있는가?
    - 해설 : 호스트 부분의 2의 거듭 제곱 형태로 비트를 계산해본다. 
    2의 10 제곱은 1024로 충분히 1000개의 호스트를 수용 가능하다. 이를 프리 픽스로 계산해보면 32-10 = 22로 프리픽스가 `/22`임을 구할 수 있다.
    기존 `/16` 에서 `/22`로 총 6칸 이동했기에 $2^6 = \mathbf{64}$ 개로 총 64개의 서브넷으로 분할 가능하다.

## day 14 : 서브넷팅 - 2

1. 서브넷 개수 계산 공식 vs 사용 가능 호스트 수 계산 공식
    - 네트워크 설계 시 혼동하기 쉬운 두 가지 기본 거듭제곱 공식의 차이를 명확히 구분해야 한다. 

    1. 생성 가능한 서브넷 개수 
        - 공식 : $2^X$ (X: 원래 기본 마스크에서 추가로 빌려온 네트워크 비트수, Borrowed Bits)
        - 주의 : 서브넷 개수를 구할 때는 양 끝 2개(네트워크, 브로드캐스트)를 빼지 않는다.
    
    2. 서브넷 당 사용 가능한 유효 호스트 수
        - 공식 : $2^H - 2$ (H: 남아있는 호스트 비트 수, Host bits)
        - 네트워크 주소와 브로드캐스트 주소 2개를 제외하기 위해 -2를 한다.

2. 특정 호스트 IP가 속한 서브넷(네트워크 ID) 역추적 기법
    - 호스트 IP와 프리픽스가 주어졌을 때 소속 서브넷을 찾는 2가지 방법
    - 방법 1 (2진수 비트 연산 방식)
        - IP 주소를 2진수로 풀어서 작성한다.
        - 프리픽스 경계선 뒤쪽의 모든 호스트 비트를 0으로 일괄 치환한다.
        - 다시 점-십진수로 변환하면 해당 호스트의 네트워크 주소가 나온다.

        - 예 : `192.168.5.57/27`에서 $57 = 00111001_2$ -> $00100000_2$
        이를 다시 Dotted Decimal로 변환하면 `192.168.5.32/27`
    
    - 방법 2 (중분값 산술 방식)
        - `/27`의 마지막 비트 가중치는 32이므로 서브넷은 0,32,64,96 ...로 진행한다.
        - 대상 호스트 IP의 마지막 옥텟이 57이므로 32와 64 사이에 속한다. 따라서 소속 서브넷은 `192.168.5.32/27`임을 암산으로 도출 가능하다.

3. Class B 네트워크(`/16`) 서브네팅
    - 기본 네트워크 마스크가 16비트인 Class B도 원리는 Class C와 완전히 동일하지만, 3번째와 4번째 옥텟(총 16개 호스트 비트)에 걸쳐 비트를 빌려올 수 있다는 점이 다르다.

    - 비트 차용 위치에 따른 증분 값 적용 옥텟
        - 3번째 옥텟에서 비트를 빌린 경우(`/17`~`/24`)
            - 증분값(Magic Number)이 3번째 옥텟에 적용된다. 
        - 4번째 옥텟까지 비트를 빌린 경우(`/25`~`/30`)
            - Class B라도 필요 서브넷 수가 많으면 4번째 옥텟까지 비트를 빌려올 수 있다.
    

### 주요 어휘

| 영문 표현 | 뜻 / 문맥 | 쓰임새 |
| :--- | :--- | :--- |
| Borrowed Bits (X) | 빌려온 비트 (차용 비트) | 서브넷을 더 쪼개기 위해 호스트 영역에서 네트워크 영역으로 전환한 비트 수 ($2^X$) |
| Magic Number (Block Size) | 증분값 (매직 넘버) | 서브넷 마스크의 마지막 네트워크 비트 자릿값으로, 다음 서브넷 주소로 넘어가는 증가 폭 |
| Boundary Octet (Interesting Octet) | 경계 옥텟 (관심 옥텟) | 프리픽스 경계선이 걸쳐 있어 서브넷 분할 계산과 비트 연산이 실제로 일어나는 특정 옥텟 |
| Host Identification | 소속 서브넷 역추적 | 특정 호스트 IP 주소의 호스트 비트를 0으로 채워 해당 호스트가 속한 네트워크 ID를 찾는 작업 |
| Class B Subnetting | Class B 서브네팅 | 16개 호스트 비트를 대상으로 3번째 및 4번째 옥텟을 쪼개어 대규모 서브넷을 구성하는 기법 |
| Equal-Sized Subnets | 균등 서브넷 | 모든 서브넷이 동일한 서브넷 마스크(프리픽스 길이)를 공유하도록 동일한 크기로 분할하는 방식 |

## day 15 : 서브넷팅 - 3

1. Class A 대규모 네트워크 서브넷팅
    - Class A는 24개의 방대한 호스트 비트를 보유하므로 원리는 값으나 계산 숫자의 자릿수가 커진다. 

    - 예시 1 : 2000개 서브넷 생성 요구
        - $2^{11} = 2,048 \ge 2,000$ 로 프리픽스가 8+11로 `/19`이다.
    
    - 예시 2 : 호스트 `10.217.187.223/11`의 상세 분석
        - 프리픽스 11 - 8 = 3으로 1110 0000 위치라고 생각하기에 쉽게 마지막 자리의 1를 고려하여 가중치의 32이를 계산 가능하다. 
        - 네트워크 주소 : `10.192.0.0`
        - 최초 유효 호스트 : `10.192.0.1`
        - 브로드캐스트 주소 : `10.223.255.255`
        - 최종 유효 호스트 : `10.233.255.254`
        - 사용 가능한 호스트 수 : `$2^{21} - 2 =$ 2,097,150대`

2. FLSM vs VLSM 개념 비교
    - FLSM (Fixed Length Subnet Mask, 고정 길이 서브넷 마스크)
        - 모든 서브넷에 동일한 크기의 프리픽스 길이를 일괄 적용하는 방식
        - 단점 : 호스트가 100대 필요한 LAN과 필요한 P2P 라우터 링크가 섞여 있을 경우 가장 큰 요구 조건에 맞추면 심각한 IP 낭비가 생기고, 작은 조건에 맞추면 대형 LAN을 수용하지 못함
    
    - VLSM(Variable Length Subnet Mask, 가변 길이 서브넷 마스크)
        - 각 서브넷(LAN 및 WAN 링크)의 필요 호스트 규모에 맞춰 서로 다른 프리픽스 길이를 유연하게 쪼개어 적용하는 방식
        - IP 주소 공간 낭비를 0에 가깝게 줄일 수 있는 현대 네트워크 설계의 핵심 기술

3. VLSM 서브넷 분할의 황금 규칙
    - VLSM 설계 시 주소가 겹치거나 꼬이지 않게 하려면 반드시 지켜야 할 단 하나의 규칙이 존재한다. 
    - **"가장 큰 호스트를 요구하는 서브넷부터 시작하여, 가장 작은 순서대로 주소 공간을 순차 배열 할 것"**

    - 큰 서브넷을 먼저 앞쪽에 큼직하게 떼어내고 남은 여유 공간을 시작점을 다음 서브넷의 네트워크 주소로 삼아 더 잘게 쪼개나가는 원리이다. 

4. VLSM 실전 설계 시나리오

    다음 위 같은 사진으로 `192.168.1.0/24`네트워크가 구성시 VLSM을 설계 해보자

    - 각 지사별 호스트 요구 조건 및 크기 순 정렬
        1. Tokyo LAN A : 110대
        2. Toronto LAN B : 45대
        3. Toronto LAN A : 29대
        4. Tokyo LAN B : 8대
        5. Router P2P link : 2대

    - 1단계 : Tokyo LAN A
        - 프리픽스 길이 : $2^7 - 2 = 126 \ge 110$ 으로 호스트 비트 7개 필요 -> `/25`
        - 블록 크기 : 128개의 IP
        - 네트워크 주소 : `192.168.1.0/25`
        - 유효 호스트 범위 : `192.168.1.1` ~ `192.168.1.126`
        - 브로드캐스트 주소 : `192.168.1.127`
    
    - 2단계 : Toronto LAN B
        - 프리픽스 길이 : $2^6 - 2 = 62 \ge 45$ 으로 호스트 비트 6개 필요 -> `/26`
        - 블록 크기 : 64개의 IP
        - 네트워크 주소 : `192.168.1.128/26`
        - 유효 호스트 범위 : `192.168.1.129`~`192.168.1.190`
        - 브로드캐스트 주소 : `192.168.1.191`
    
    - 3단계 : Tornto LAN A
        - 프리픽스 길이 : $2^5 - 2 = 30 \ge 29$ 으로 호스트 피트 5개 필요 -> `/27`
        - 블록 크기 : 32개의 IP
        - 네트워크 주소 : `192.168.1.192/27`
        - 유효 호스트 범위 : `192.168.1.193`~`192.168.1.222`
        - 브로드캐스트 주소 : `192.168.1.223`
    
    - 4단계 : Tokyo LAN B
         - 프리픽스 길이 : $2^4 - 2 = 14 \ge 8$ 으로 호스트 피트 5개 필요 -> `/28`
        - 블록 크기 : 16개의 IP
        - 네트워크 주소 : `192.168.1.224/28`
        - 유효 호스트 범위 : `192.168.1.225`~`192.168.1.238`
        - 브로드캐스트 주소 : `192.168.1.239`
    
    - 5단계 : Router P2P link
         - 프리픽스 길이 : 2의 호스트 전용으로 가장 널리 권장되는 `/30`사용
        - 블록 크기 : 4개의 IP
        - 네트워크 주소 : `192.168.1.240/30`
        - 유효 호스트 범위 : `192.168.1.241`~`192.168.1.242`
        - 브로드캐스트 주소 : `192.168.1.243`



### 주요 어휘

| 영문 표현 | 뜻 / 문맥 | 쓰임새 |
| :--- | :--- | :--- |
| VLSM (Variable Length Subnet Mask) | 가변 길이 서브넷 마스크 | 한 네트워크 안에서 각 세부 서브넷마다 서로 다른 크기의 서브넷 마스크를 부여하는 설계 기술 |
| FLSM (Fixed Length Subnet Mask) | 고정 길이 서브넷 마스크 | 모든 서브넷에 단일한 동일 서브넷 마스크를 적용하는 전통적이고 경직된 서브넷 방식 |
| Largest to Smallest Rule | 대규모 우선 할당 원칙 | VLSM 설계 시 IP 블록의 중복을 방지하기 위해 호스트 요구량이 가장 큰 서브넷부터 순서대로 배정하는 규칙 |
| Subnet Allocation | 서브넷 배정 | 계산된 서브넷 블록을 실제 각 지사의 LAN 또는 WAN 링크 인터페이스에 매핑하는 작업 |
| Point-to-Point Link (/30) | 점대점 회선 (/30 적용) | CCNA 시험 표준상 2개의 라우터 간 직결 링크에 부여하는 가장 보편적인 2호스트 전용 서브넷 |
