## day7 : IPv4 주소 체계 - 1

1. Layer 3(네트워크 계층) 복습 및 라우터의 경계
    - Layer 3의 핵심역할
        - 서로 다른 LAN에 위치한 단말 간의 통신 경로를 제공한다.
        - 하드웨어 각인 주소(MAC 주소)와 분리된 논리적 주소(IP주소)를 부여한다.
        - 복잡한 대규모 망에서 최적의 경로를 선택하는 경로 선택(Path Selection/Routing)을 담당한다.
        - Layer 3에서 동작하는 핵심 장비가 라우터이다.
    
    - 스위치 vs 라우터의 경계 구분
        - 스위치는 단지 기존 LAN 망을 물리적으로 확장할 뿐, 서로 다른 네트워크를 분리하지 못한다.
        - 라우터 인터페이스는 브로드캐스트 패킷을 외부로 넘기지 않고 차단하므로, 서로 다른 L3 네트위크의 분리 경계가 된다.
        - 라우터는 연결된 네트워크 마다 각각 서도 다른 IP IP주소를 인터페이스 별로 부여받아야 한다.
        (ip주소는 논리적 주소 임으로 다른 LAN이라면 서로 완벽히 같은 ip 주소를 가질 수 있따.)

2. IPv4 주소의 구조(Dotted Decimal & Binary, 점이 찍힌 10진수와 2진수)
    <img width="733" height="418" alt="Image" src="https://github.com/user-attachments/assets/f9b4f0ed-3ff6-4246-9f81-1de718263218" />
    - 크기 : 32비트(4바이트)
    - 옥텟 : 32비트를 8비트씩 4개 묶음으로 쪼갠 단위이다.
    - 점-십진수 표기법(Dotted Decimal Notation) : 32자리 2진수를 8비트 옥텟을 10진수로 변환한 후 점으로 구분하여 표기한다.

3. 2진수 <-> 10진수 변환 공식
    - 8비트 옥텟의 각 비트 자릿값은 오른쪽 부터 2배씩 커지는 $2^{n} 가중치를 가진다.

4. 네트워크 부분 vs 호스트 부분 & 서브넷 마스크
    - IP 주소는 단말이 속한 네트워크를 나타내는 네트워크 부분과 해당 네트워크 내 특정 단말을 식별하는 호스트 부분으로 나뉜다. 

    - 프리픽스 길이 (Prefix Length /CIDR 표기법)
        - CIDR(Classless Inter-Domain Routing, 사이더)표기법 : IP 주소 뒤에 슬래시와 숫자를 붙여 서브넷 마스크를 간결하게 표현하는 방식이다.
        - / 뒤의 숫자가 앞쪽부터 몇 번째 비트까지가 네트워크 부분인지 나타낸다. 
        ex : `/24`, 앞쪽 24비트가 네트워크, 마지막 8비트가 호스트를 나타낸다.

    - 넷마스크/서브넷 마스크(Netmask/Subnet Mask)
        - 넷 마스크 : 기존 주소 클라스(A,B,C 클래스)의 네트워크 영역을 통째로 나타낼 주로 사용
        - 서브넷 마스크 : 주어진 네트워크를 더 조각조각 나누어 사용할 때 적용하는 마스크
        - 네트워크 비트는 전부 1, 호스트 비트는 전부 0으로 채워 Dotted Decimal 형식으로 표현한 주소이다. 
            - `/8` : 255.0.0.0
            - `/16` : 255.255.0.0
            - `/24` : 255.255.255.0

5. 클래스풀 주소 체계
    - IP주소의 첫 번째 옥텟의 값 범위에 따라 5개의 클래스로 분류된다.

    | 클래스 | 시작 2진 비트 | 첫 옥텟 범위 | 기본 프리픽스 / 넷마스크 | 네트워크 수 | 네트워크당 사용 가능 호스트 수 ($2^H - 2$) | 주요 용도 |
    | :---: | :---: | :---: | :---: | :---: | :---: | :--- |
    | **Class A** | `0...` | 1 ~ 126 ($0 \sim 127$) | /8 (`255.0.0.0`) | 128개 | 약 1,677만 대 ($2^{24} - 2$) | 초대형 기관/기업용 |
    | **Class B** | `10...` | 128 ~ 191 | /16 (`255.255.0.0`) | 약 16,000개 | 65,534대 ($2^{16} - 2$) | 중대형 네트워크 |
    | **Class C** | `110...` | 192 ~ 223 | /24 (`255.255.255.0`) | 약 200만 개 | 254대 ($2^8 - 2$) | 소규모 LAN |
    | **Class D** | `1110...` | 224 ~ 239 | - | - | - | 멀티캐스트(Multicast) 전용 |
    | **Class E** | `1111...` | 240 ~ 255 | - | - | - | 연구/실험용 예약 (미사용) |

    - 특수 주소 : 127.0.0.0/8
        - ClassA 범위(0~127) 중 `127.0.0.0 ~ 127.255.255.255`는 로컬 호스트 루프백용도로 예약되어 있다.
        - 자신의 TCP/IP 프로토콜 스택이 정상 작동하는지 점검하기 위한 주소이며, 외부 네트워크로 패킷이 나가지 ㅇ낳고 기기 내부에서 스스로 응답합니다.
        - 실제 할당 가능한 Class A의 첫 옥텟 범위는 일반적으로 1~126으로 간주한다.

6. 네트워크 주소 vs 브로드캐스트 주소 vs 호스트 할당 주소
    - 네트워크 대역 내에서 호스트에게 부여할 수 없는 예약 주소 2가지가 존재하므로, 사용 가능한 호스트 개수는 항상 $2^H - 2$개가 된다.
    
    1. 네트워크 주소
        - 호스트 부분이 모두 0인 주소
        - 네트워크 전체를 대표하는 식별자로 쓰이며, 호스트 인터페이스에 부여할 수 없다.
    2. 브로트캐스트 주소
        - 호스트 부분이 모두 1인 주소
        - 해당 로컬 네트워크의 모든 단말에게 패킷을 동시에 전송할 때 사용하는 Layer 3 목적지 주소이다.
        - 이 패킷이 L2로 캡슐화될 때 목적지 MAC 주소는 `FFFF.FFFF.FFFF` 가 된다.
        - 호스트에 개별 부여할 수 없다.
    3. 실제 사용 가능한 유효 호스트 주소
        - 네트워크 주소 바로 다음 번호 부터 브로드 캐스트 주소 바로 앞 번호까지 할당 가능하다.
        예시로 `192.168.1.0` 는 최초 유호 ip가 `192.168.1.1` 이고 최종 유효 ip가 `192.168.1.255`이다.


### 주요 어휘

| 영문 표현 | 뜻 / 문맥 | 쓰임새 |
| :--- | :--- | :--- |
| Octet | 옥텟 | 8개의 비트로 구성된 바이트 단위 (IPv4 주소는 4개의 옥텟으로 구성) |
| Dotted Decimal Notation | 점-십진수 표기법 | 32비트 2진수를 8비트씩 10진수로 변환해 점(.)으로 구분하는 인간 친화적 표기법 |
| Network Portion | 네트워크 부분 | IP 주소에서 호스트가 속한 서브넷/네트워크 ID를 식별하는 상위 비트 영역 |
| Host Portion | 호스트 부분 | 동일 네트워크 내에서 개별 단말(호스트)을 고유하게 식별하는 하위 비트 영역 |
| Prefix Length | 프리픽스 길이 | IP 주소 뒤에 '/숫자' 형식으로 네트워크 비트의 길이를 명시하는 표기법 (CIDR) |
| Netmask / Subnet Mask | 서브넷 마스크 | 네트워크 비트는 1, 호스트 비트는 0으로 나타내어 네트워크 경계를 분리하는 32비트 값 |
| Classful Addressing | 클래스풀 주소 지정 | IP의 첫 번째 옥텟 범위에 따라 A, B, C, D, E 클래스로 규격화했던 초기 주소 체계 |
| Loopback Address | 루프백 주소 | 자기 자신의 TCP/IP 스택을 시험하기 위해 예약된 127.0.0.0/8 대역의 특수 주소 |
| Multicast Address | 멀티캐스트 주소 | 특정 수신자 그룹 전체에 1:N으로 패킷을 전송하기 위해 예약된 Class D 대역 주소 |
| Network Address | 네트워크 주소 | 호스트 비트가 모두 0인 주소로 네트워크 자체를 대표하며 단말에 할당 불가 |
| Broadcast Address | 브로드캐스트 주소 | 호스트 비트가 모두 1인 주소로 네트워크 내 전체 호스트에 동시 전송할 때 사용 |
| Usable Host Address | 유효 호스트 주소 | 네트워크 주소와 브로드캐스트 주소를 제외한 실제 단말/인터페이스에 부여 가능한 IP |

## day8 : IPv4 주소 체계 - 2

1. IPv4 클래스 및 사용 가능 범위 재정리
    - Class A 범위에 대한 규정 정리
        - 2진수 첫 비트가 0인 이론적 범위는 `0.0.0.0 ~ 127.255.255.255`이다.
        - `0.0.0.0/8`(기본/예약 주소)과 `127.0.0.0/8`(루프백 주소) 대역은 특수 목적으로 예약되어 있다.
        - 실제 호스트나 네트워크에 할당 가능한 유효 범위는 1~126이다.

2. 네트워크 핵심 5요소 산출 공식 ($2^H - 2$)
    - 네트워크 비트 수를 N, 호스트 비트 수를 H라고 할 때 (H + N = 32)

    1. 네트워크 주소,아이디
        - 호스트 비트를 모두 0으로 설정한 주소
        - 네트워크 자체를 식별하는 주소로 호스트에 부여할 수 없다.
    
    2. 브로드캐스트 주소
        - 호스트 주소를 모두 1로 설정한 주소
        - 해당 서브넷의 모든 호스트로 패킷을 전송할 때 사용하며 호스트에 부여할 수 없다.
    
    3. 최대 사용 가능 호스트 수
        - Class A (/8, $H=24$): $2^{24} - 2 = \mathbf{16,777,214}$개 
        - Class B (/16, $H=16$): $2^{16} - 2 = \mathbf{65,534}$개 
        - Class C (/24, $H=8$): $2^8 - 2 = \mathbf{254}$개
    
    4. 최초 사용 가능 주소
        - 공식 : 네트워크 주소 + 1
        - 호스트 부분의 마지막 비트를 1로 바꾼 주소
    
    5. 최종 사용 가능 주소 
        - 공식 : 브로드캐스트 주소 - 1
        - 브로드캐스트 주소에서 호스트 부분의 마지막 비트를 0으로 바꾼 주소

3. 시스코 라우터 인터페이스 IP 설정 실습

    ```
    R1# configure terminal
    R1(config)# interface <인터페이스명>     ! (예: int g0/0)
    R1(config-if)# ip address <IP주소> <서브넷마스크>
    R1(config-if)# no shutdown
    ```

    - 서브넷 마스크 입력 규칙
        - 시스코 IOS는 CLI에서 `/24` 같은 프리픽스 표기 대신, 점-십진수 서브넷 마스크를 직접 입력해야 한다.
    
    - `no shutdown` 필수
        - 시스코 라우터 인터페이스는 기본 설정이 비활성화(`administratively down`)상태이므로 반드시 `no shutdown`을 입력해야 켜진다.
        - 스위치 포트는 같은 네트워크 안에서 바로 작동 시키기 위해서 기본적으로 활성화 상태이다. 
    
    - 인터페이스 설명(Description) 추가
        - `R1(config-if)# description <설명문구>    ! (예: description ### Connected to SW1 ###)`
        - 인터페이스(포트)에 메모를 붙이는 기능으로 기능적으로 아무로 영향을 안주는 주석 구문으로 나중에 장애가 생겼을 해당 포트를 명시하기 위해 주로 사용한다.
    
4. 인터페이스 상태 점검 필수 확인 명령어 (Show Commands)

    1. `show ip interface brief`(단축 : `sh ip int br`)
        - 모든 인터페이스의 핵심 요약 정보를 한눈에 파악한다.
        
        - 주요 확인 열 : 
            - `Interface` : 인터페이스 포트 이름
            - `IP-Address` : 부여된 IP 주소 (미설정시 `unassigned`)
            - `Method` : IP 할당 방식 (`manual`:수동 설정, `unset`:설정 안됨, `DHCP`:자동할당)
            - `Status`(Layer1-물리 계층 상태) : 케이블 연결 및 `no shutdown` 여부 확인(`up`, `administratively down`)
            - `Protocol`(Layer2-데이터링크 계층 상태) : 프레이밍 및 L2 프로토콜 통신 정상 여부(`up`, `down`)
        
        - 핵심 규칙 : L1(status)가 down이면 L2(protocol)는 무조건 down이다.
    
    2. `show interface <인터페이스명>`
        - 특정 포트의 상세 정보를 출력한다.
        - L1/L2 동작 상태, 하드웨어 규격, MAC 주소 및 BIA(각인 주소), IP 주소, MTU, 대역폭(BW), 전송 카운터 에러 등을 확인한다.
        (BIA : 공장에서 나올 때 고정된 원래 주소, MAC : 현재 장비가 통신할 때 사용 중인 주소)
    
    3. `show interfaces description`(단축형 : `sh int desc`)
        - 포트별 상태와 함께 설정해 둔 설명(Description)문구를 확인한다.


### 주요 어휘

| 영문 표현 | 뜻 / 문맥 | 쓰임새 |
| :--- | :--- | :--- |
| Network ID (Network Address) | 네트워크 식별자 (네트워크 주소) | 호스트 비트가 전부 0인 주소로 라우터가 경로를 식별하는 기준값 |
| Usable Host Address | 유효 호스트 주소 | 네트워크 ID(+1)부터 브로드캐스트(-1) 사이의 실제 장비 할당 가능 주소 |
| Administratively Down | 관리적 다운 (차단 상태) | 관리자가 인터페이스에 'shutdown' 명령어를 적용하여 L1이 꺼진 상태 |
| Line Protocol | 라인 프로토콜 | 인터페이스의 Layer 2(데이터링크 계층) 통신 작동 상태 |
| Interface Configuration Mode | 인터페이스 설정 모드 | 프롬프트 '(config-if)#' 상태로 포트 단위 매개변수(IP 등)를 지정하는 모드 |
| Subnet Mask | 서브넷 마스크 | IP 주소 뒤에 넷마스크 255.255.x.x 형식으로 네트워크/호스트 경계를 지정 |
| Context-Sensitive Help | 문맥 감지 도움말 | CLI 명령어 작성 중 '?' 키를 입력하여 다음 가능한 매개변수를 확인하는 기능 |
| Description | 인터페이스 설명 | 관리자가 인터페이스 용도(연결 대상 등)를 알아보기 쉽게 남기는 주석 라벨 |
