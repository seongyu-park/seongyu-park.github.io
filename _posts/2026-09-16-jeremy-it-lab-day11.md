## day11 - 라우팅 기초

1. 라우팅의 정의와 학습 방식
    - 라우팅의 정의 : 라우터가 IP 패킷을 수신했을 때 목적지 네트워크까지 최적의 경로를 결정하여 올바르게 전달(포워딩)하는 전반적인 프로세스이다. 

    - 테이블 비교
        - 스위치는 L2 목적지 물리 주소를 기록하는 MAC 주소 테이블을 유지한다.
        - 라우터는 알려진 목적지 L3 네트워크 목록과 전달 지침을 기록하는 라우팅 테이블을 유지한다.
    
    - 경로 학습 방식 2가지
        - 동적 라우팅(Dynamic Routing) : OSPF 등 동적 라우팅 프로토콜을 통해 라우터까리 라우팅 정보를 자동으로 교환하여 테이블을 구축
        - 정적 라우팅(Static Routing) : 네트워크 관리자가 수동을 직접 경로를 입력
        - 해당 포스트에서는 두 범주에 속하지 않고, 인터페이스 활성화 시 시스템에 의해 자동으로 등록되는 특수 경로(Connected & Local)를 중점적으로 다룬다.

2. 라우팅 테이블 구조 및 자동 생성 경로
    - 라우터 인터페이스에 IP 주소를 설정하고 `no shutdown`으로 활성화 하면, 라우팅 테이블(`show ip route`)에 포트당 2개의 경로가 자동으로 등록된다. 
    ```
    C    192.168.1.0/24 is directly connected, GigabitEthernet0/2
    L    192.168.1.1/32 is directly connected, GigabitEthernet0/2
    ```

    1. Connected 경로(코드 C)
        - 대상 : 인터페이스가 속한 서브넷/네트워크 전체(`/24`등 설정된 서브넷 마스크 적용)
        - 예를 들면 `g0/2` 포트 IP `192.0.168.1.1/24`를 부여하면, 해당 인터페이스는 같은 네트워크에 있는 `192.168.1.0 ~ 192.168.1.255` 범위 전체를 목적지로 인식한다.
        - 해당 상태는 동일한 스위치/케이블로 붙어있는 상태로 다른 라우터에 넘길 필요 없이 `g0/2` 포트로 패킷을 바로 밀어내어 대상 기기에 직접 전달한다. 
    
    2. Local 경로(코드 L)
        - 대상 : 라우터 인터페이스 자체에 실제 할당된 고유 IP 주소 단 하나, 라우터 포트 본인에게 할당된 고유 IP 주소
        - 프리픽스 마스크 : 특정 단일 호스트만을 지칭하기 위해 항상 `/32` 넷 마스크를 사용한다(`255.255.255.255`).
        - 자체 수신 : 패킷을 외부 다른 장비로 포워딩 할 필요 없이 L2/L3 헤더를 벗겨내고 라우터 내부 OS(Ping응답, SSH 접속, 라우팅 정보 교환)로 전달하여 라우터가 직접 응답한다.

3. 경로 매칭(Route Matching)과 최장 프리픽스 매칭(LPM) 규칙
    - 라우터가 목적지 IP를 가진 패킷을 받았을 때 라우팅 테이블에서 최적 경로를 결정하는 2대 핵심 규칙이다. 

    1. 경로 매칭
        - 패킷의 목적지 IP가 라우팅 테이블에 정의된 네트워크 범위 내에 포함되어야 해당 경로와 매치 된 것으로 본다. 
    
    2. 최장 프리픽스 매칭(Longest Prefix Match / Most Specific Match)
        - 하나의 패킷 목적지 IP가 라우팅 테이블의 여러 경로와 동시에 매치될 경우, 네트워크 비트수가 가장 긴 (프리픽스 길이가 가장 큰/가장 구체적인)경로를 최종 선택한다.

4. 라우터 vs 스위치 결정적 동작 차이
    - 스위치(Switch)
        - 프레임의 목적지 MAC 주소를 모를 때 인입 포트를 제외한 모든 포트로 플러딩(Floodig)한다.
        - 테이블에서 항상 완전 일치하는 주소만 찾느다. 
    
    - 라우터(Router)
        - 패킷의 목적지 IP와 매치되는 경로가 라우팅 테이블에 전혀 없으면, 패킷을 절대 플러딩하지 않고 즉시 폐기한다.
        - 테이블에서 가장 구체적인 경로를 탐색한다.

5. `show ip route` 출력 화면의 기타 안내 문구
    - 라우팅 테이블 상단에 출력 되는 `192.168.1.0/24 is variably subnetted, 2 subnets, 2 masks` 같은 문구는 실제 라우팅 경로가 아니다.
        - `192.168.1.0`(부모 네트워크) : 아래에 나올 하위 경로들이 속해 있는 기준 네트워크 범위
        - `is variably subnetted`(가변 서브넷) : 해당 범위 안에 서브넷 마스크 길이가(/24, /32)가 서로 다른 다양한 경로가 섞여 있다.
        - `2 subnets`(하위 경로 개수) : 이 그룹 아래에 실제 라우팅 경로가 2개 존재한다.
        - `2 masks`(마스크 종류 개수) : 사용된 서브넷 마스크의 종류가 2가지(예 /24, /32)라는 뜻이다.
    
    - 해당 클래스 플 네트워크 범위 내에 서로 다른 서브넷 마스크를 가진 세부 세브넷 경로들이 존재함을 요약해 주는 시스템 헤더 헤드라인일 뿐, 경로 부석 시에 이를 무시하고 아래의 실제 경로(`C, L`)들만 확인하면 된다.


### 주요 어휘

| 영문 표현 | 뜻 / 문맥 | 쓰임새 |
| :--- | :--- | :--- |
| Routing Table | 라우팅 테이블 | 패킷 포워딩 경로 및 목적지 네트워크 정보가 등록된 라우터의 핵심 데이터베이스 |
| Connected Route (C) | 직접 연결 경로 | 라우터 인터페이스에 연결된 서브넷 전체를 나타내며 인터페이스 활성화 시 자동 등록 |
| Local Route (L) | 로컬 주소 경로 | 라우터 인터페이스 자체의 IP 주소를 가리키는 /32 경로로 패킷의 자체 수신에 사용 |
| Longest Prefix Match (LPM) | 최장 프리픽스 매칭 | 여러 경로가 매치될 때 서브넷 마스크 비트 수(프리픽스 길이)가 가장 긴 경로를 우선 선택 |
| Most Specific Route | 가장 구체적인 경로 | IP 대역 범위가 가장 좁고 상세하여 라우터가 최우선으로 선택하는 경로 |
| Next Hop | 넥스트 홉 | 목적지 네트워크로 가기 위해 패킷을 넘겨주어야 할 경로 상의 바로 다음 라우터 IP |
| Drop | 폐기 (드롭) | 라우팅 테이블에 일치하는 목적지 경로가 없을 때 라우터가 패킷을 버리는 동작 |
| WAN (Wide Area Network) | 광역 통신망 | 서로 다른 도시나 국가 등 지리적으로 멀리 떨어진 LAN들을 라우터로 연결한 대규모 망 |
| Hop Count | 홉 수 | 패킷이 최종 목적지에 도달하기까지 거쳐 가는 라우터의 개수 |
| Variably Subnetted | 가변 서브넷 구성 | 라우팅 테이블 내에 동일 주요 네트워크에 속하면서 마스크 길이가 다른 경로들이 공존함 |

## day 12 : 정적 라우팅

1. 원격 네트워크(Remote Network)와 정적 라우팅의 필요성
    - Connected/Local 경로의 한계
        - 인터페이스 IP 설정으로 자동 등록되는 C와 L 경로는 오직 자신과 직접 맞닿은 네트워크만 전달할 수 있다. 
        - 라우터와 직접 연결되지 않는 원격 네트워크로 향하는 패킷은 라우텡 테이블에 매칭되는 정보가 없으므로 라우터가 즉시 폐기한다.
    
    - 정적 라우팅
        - 네트워크 관리자가 원격 목적지 네트워크에 도달하기 위한 경로를 CLI 명령어로 수동 구성하여 라우팅 테이블에 주입하는 방식이다.
    
2. 디폴트 게이트웨이(Default Gateway)
    - 동작 원리
        - 엔드 호스트의 PC는 동일 LAN 내부 호스트와는 직접 통신(L2)하지만, 로컬 네트워크 외부로 나가는 모든 트래픽은 디폴트 게이트 웨이(기본 라우터)로 던진다.
    
    - 단말 내부에서의 의미
        - 리눅스나 윈도우 단말에 설정하는 게이트웨이의 주소는 내부적으로 `0.0.0.0/0` 디폴트 라우터로 등록된다.
        - 구체적인 다른 경로가 없으면 무조건 게이트웨이로 패킷을 전송한다.
        - 즉 내부 LAN 안에 없는 주소를 기본 게이트 웨이로 보내는 것이다.

3. 양방향 도달 가능성
    - 네트워크 통신이 성공하면 가는 길 뿐 아니라 되돌아오는 길의 경로도 반드시 완성되어야 한다. 
    - 만일 가능 경로만 있고 돌아오는 경로가 없으면 도착 확인에 대한 응답 패킷이 경로가 없으므로 드롭시켜 통신에 실패하게 된다.
    - 중간 라우터들은 경로 상의 모든 네트워크를 알 필요는 없으며 출발지 네트워크와 최종 목적지 네트워크로 가는 다음 홉(Next-Hop)정보만 가지고 있으면 된다.

4. 패킷 전달 중 L2 vs L3 헤더 변화 (Life of a Packet)
    - Layer 3(IP 헤더)
        - 출발지 IP와 목적지 IP는 전 여정 동안 변하지 않고 고정된다.
    
    - Layer 2(이더넷 프레임):
        - 라우터를 거칠 때마다 기존 L2 헤더/트레일러는 벗겨지고(Decapsulation), 다음 홉 장비로 넘어가기 위한 세로운 L2 헤더/트레일러로 다시 씌워진다.(Re-encapsulation)
        - 출발지 MAC과 목적지 MAC은 매 홉을 건널 때마다 계속 바뀐다.
        - 목적지 IP와 목적지 MAC이 동일한 기기를 가리키는 순간은 패킷이 최종 목적지 네트워크에 도달하여 목적지 LAN의 라우터가 해당 노드로 프레임을 던지는 마지막 순간 뿐이다. 

5. 시스코 정적 라우팅 설정 문법
    - 전역 설정 모드(`config#`)에서 `ip route`명령어를 사용한다.
    
    1. Next-Hop IP만 지정하는 방식(가장 일반적인 형태)
    ```
    Router(config)# ip route <목적지네트워크> <서브넷마스크> <Next-Hop IP>
    ! 예: R1에서 R3(13.3)을 통해 4.0/24 네트워크로 가도록 설정
    R1(config)# ip route 192.168.4.0 255.255.255.0 192.168.13.3
    ```

    - 라우팅 테이블에는 `S 192.168.4.0/24 [1/0] via 192.168.13.3`형태로 표시된다.
        - `S`(Static Route/정적 경로) : 관리자가 수동으로 직접 명령어을 입력해 설정한 경로라는 뜻이다.
        - `192.168.4.0/24` : 목적지 네트워크
        - `[1/0]`(AD/Metric)
            - AD(Administrative Distance, 관리 거리) : 경로 출처의 신뢰도(0~255)로 수가 작을 수록 더 신뢰한다. 
            - Metric(메트릭/측정값) : 해당 경로로 갈 때 드는 비용/거리 로 정적 경로는 건너편 라우터로 바로 넘기므로 비용 계산이 필요 없어 0으로 표시된다.
    
    2. 출구 인터페이스(Exit Interface)만 지정하는 방식
        - 출구 인터페이스 : 패킷이 내 라우터 밖으로 나가는 내 라우터의 물리적/논리적 포트 자체
        ```
        Router(config)# ip route <목적지네트워크> <서브넷마스크> <로컬출구인터페이스>
        ! 예: R2에서 1.0/24로 갈 때 자신의 g0/0 포트로 내보내도록 설정
        R2(config)# ip route 192.168.1.0 255.255.255.0 g0/0
        ```
        - 주의점 : 라우팅 테이블에는 `is directily connected`로 출력되지만 실제 직결된 것은 아니기에, 정상 통신을 위해 내부적으로 Proxy ARP 기능에 의존하게 된다.
    
    3. 출구 인터페이스와 Next-Hop IP를 둘 다 지정하는 방식
        ```
        Router(config)# ip route 192.168.4.0 255.255.255.0 g0/1 192.168.24.4
        ```
        - 둘다 지정한 것이 각각 하나만 지정한 것에 비해 라우터의 불필요한 연산과 ARP 폭풍을 막아주는 안전한 설정 방법이다.

6. 디폴트 라우터 (Default Route / Gateway of Last Resort)
    - 주소와 서브넷 마스크 비트가 모두 0인 `0.0.0.0/0` 경로
    - 모든 IP 대역을 포괄하므로 가장 덜 구체적인 경로이다. 
    - 라우팅 테이블에 일치하는 구체적인 경로가 없을 때 마지막 최후의 수단으로 패킷을 전송하는 경로(주로 인터넷 ISP방향으로 트래픽을 내보낼 때 사용)

    - 시스코 라우터 설정 명령어
    ```
    Router(config)# ip route 0.0.0.0 0.0.0.0 <Next-Hop IP 또는 출구인터페이스>
    ! 예: 인터넷 라우터(203.0.113.2)로 디폴트 라우트 설정
    R1(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.2
    ```
    시스코 IOS에서는 프리픽스를 사용할 수 없고 접-십진수 넷마스크를 입력해야 한다.

    - 라우팅 테이블 표기 확인
        - `Gateway of Last Resort is 203.0.113.2 to network 0.0.0.0`문구가 활성화 된다.
        - 경로 목록에 `S* 0.0.0.0/0 [1/0] via 203.0.113.2`로 출력되며 코드 옆의 `*`는 디폴트 후보 경로(Candidate Default)임을 나타낸다.


### 주요 어휘

| 영문 표현 | 뜻 / 문맥 | 쓰임새 |
| :--- | :--- | :--- |
| Static Route | 정적 경로 | 관리자가 목적지 네트워크, 마스크, Next-Hop을 수동으로 입력해 생성한 경로 (코드: S) |
| Next Hop | 넥스트 홉 | 패킷을 목적지로 보내기 위해 거쳐야 하는 경로 상의 바로 다음 라우터 IP 주소 |
| Exit Interface | 출구 인터페이스 | 패킷을 내보낼 라우터 자신의 로컬 인터페이스 포트 |
| Remote Network | 원격 네트워크 | 라우터와 직접 케이블로 맞닿아 있지 않아 라우팅 경로가 반드시 필요한 네트워크 |
| Two-Way Reachability | 양방향 도달 가능성 | 송신자의 요청과 수신자의 응답 경로가 모두 확보되어 상호 통신이 가능한 상태 |
| Default Gateway | 디폴트 게이트웨이 | 단말(호스트)이 외부 원격 네트워크로 나갈 때 패킷을 전달하는 첫 번째 기본 라우터 |
| Default Route | 기본 경로 (디폴트 라우트) | 목적지 0.0.0.0/0을 가리키는 경로로 일치하는 경로가 없을 때 최후에 선택되는 경로 |
| Gateway of Last Resort | 최후의 게이트웨이 | 라우터가 매칭되는 경로를 찾지 못했을 때 패킷을 넘겨주는 최종 디폴트 라우트 목적지 |
| Candidate Default (*) | 디폴트 후보 | 라우팅 테이블에서 'S*'처럼 별표로 표시되며 디폴트 경로로 채택될 수 있는 후보 경로 |
| Re-encapsulation | 재캡슐화 | 라우터가 홉을 넘길 때 이전 L2 헤더를 버리고 새 L2 헤더/트레일러를 씌우는 과정 |
| Proxy ARP | 프록시 ARP | 출구 인터페이스만 지정된 정적 라우트에서 다음 장비의 MAC을 대신 응답해 주는 기술 |
